# 사용 가이드

## 처음 연결

1. `python run.py` 또는 배포 폴더의 `CaptainTunnel.exe`를 실행합니다.
2. 경유 SSH 서버 주소·포트·계정·인증 방식을 확인합니다. 기존 IFMS 기본값이 들어 있으므로 다른 환경에서는 수정합니다.
3. 필요한 터널을 추가하거나 기존 목록에서 고릅니다. 내 PC 포트는 서로 달라야 합니다.
4. 시작을 누르고 비밀번호 또는 키 파일 암호를 입력합니다. 처음 연결하는 서버는 별도 경로로 받은 호스트 키 지문과 대조합니다.
5. 상태가 열림이면 DB 도구·브라우저·SSH 클라이언트에서 `127.0.0.1:<내 PC 포트>`로 접속합니다.

원격 대상 `127.0.0.1`은 **경유 SSH 서버 자신**을 뜻합니다. 내 PC 주소와 구분합니다. SSH 연결이 끊겨도 로컬 리스너는 유지하며, 새 연결은 재연결을 최대 20초 기다립니다. 끊긴 기존 DB 세션 자체가 복원되는 것은 아니므로 클라이언트에서 다시 접속해야 합니다.

## 목록·자동 시작

- 터널을 더블클릭하거나 시작·중지 버튼으로 제어합니다. 이름 머리글을 누르면 자연 정렬합니다.
- `자동` 체크는 프로그램 자동 시작 또는 서비스 실행 대상입니다.
- `도구 → 표준 터널 목록 반영`은 기존 IFMS 표준 목록과 비교하여 이름을 맞추고 빠진 항목을 추가합니다. 사용자 포트와 자동 여부는 기존 값을 유지합니다.
- `config.ini`의 `[tunnels] show_mig`, `show_dev`, `show_prd`로 망별 표시·실행을 제어합니다. 기본값은 MIG·개발망 표시, 공사망 숨김입니다.
- 숨긴 터널은 설정에 남지만 전체 시작·서비스 대상에서 제외됩니다. GUI는 재실행하고 서비스는 약 2초 후 변경을 반영합니다.

## Windows 서비스

1. 빌드된 EXE 폴더를 계속 사용할 고정 위치에 둡니다.
2. 처음에는 화면에서 연결을 검증하고 호스트 키를 등록합니다.
3. 필요한 터널을 자동 대상으로 선택합니다.
4. 서비스 설치를 누르고 서비스용 비밀번호를 저장한 다음 UAC를 승인합니다.
5. 서비스 상태·로그를 확인하고 GUI를 닫은 뒤 로컬 포트로 접속합니다.
6. 배포 검증 PC에서는 재부팅 후 GUI를 실행하지 않은 상태에서도 접속되는지 확인합니다.

서비스 이름은 `CaptainTunnel`입니다. 설치·제거에는 관리자 권한이 필요합니다. 소스 GUI에서 서비스 설치는 지원하지 않으며 배포 EXE를 사용합니다. 데이터 폴더가 사용자별 대체 위치로 바뀐 경우에는 GUI와 LocalSystem이 다른 설정을 볼 수 있어 설치를 막습니다.

서비스 비밀번호는 **PC 범위 DPAPI**로 보관합니다. 같은 PC의 다른 계정도 파일을 읽으면 복호화할 수 있으므로 폴더 접근 권한을 관리합니다. 사용자 범위로 기억한 비밀번호는 로그인한 사용자용입니다.

서비스와 예전 IFMS 판은 식별자가 다르지만 같은 로컬 포트를 동시에 열 수는 없습니다. [이관 가이드](migration.md)를 따릅니다.

## 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 포트 사용중 | MobaXterm·Docker·기존 터널 프로그램과 내 PC 포트 충돌 |
| SSH 인증 실패 | 계정·비밀번호·키 파일 경로·키 파일 암호 |
| 대상 연결 실패 | 경유 서버에서 원격 대상 주소·포트까지 접근 가능한지 |
| 호스트 키 불일치 | 서버 교체 여부와 실제 지문을 먼저 확인하고 초기화 |
| GUI는 연결되지만 서비스는 실패 | 서비스용 암호·프로그램 폴더 known_hosts·키 파일 접근 권한 |
| 목록에 공사망이 없음 | `config.ini`의 `show_prd` 값 |
| 설정 오류 | 오류 원본은 `.broken_<시각>`으로 보관하고 기본값으로 시작하는지 |

`Pre-authentication banner`는 서버의 접속 안내문일 수 있습니다. 그 문구만으로 실패를 판단하지 말고 실제 인증 결과를 확인합니다. 상태 줄에 표시되는 설정 폴더와 그 안의 `logs/`가 진단 기준입니다.
