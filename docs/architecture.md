# 아키텍처

## 모듈

`cli.py`가 인수와 플랫폼을 확인하고 필요할 때만 `application.py`를 불러옵니다. 도움말과 버전 조회는 Tkinter·Paramiko 없이 동작합니다. `paths.py`는 진입점과 데이터 경로를, `configuration.py`는 설정 검증을 담당합니다. 버전의 정본은 `__init__.py`입니다.

원본의 GUI·네트워크·Windows API 코드는 `application.py`로 이관했습니다. 이번 작업에서는 기존 동작을 유지하면서 진입점·경로·설정 검증을 분리했습니다. 네트워크와 GUI를 별도 모듈로 나누는 작업은 후속 과제입니다.

## 연결 경로

```text
DB 도구 / 브라우저 / SSH 클라이언트
  → 내 PC 리스너(Forwarder)
  → 단일 SSH Transport(Engine)
  → direct-tcpip 채널
  → 경유 서버에서 보이는 대상 호스트·포트
```

- `Engine`: SSH supervisor 스레드, 연결·keepalive·재시도 상태를 관리합니다.
- `Forwarder`: 터널별 리스너와 접속별 중계 스레드를 관리합니다.
- `Runner`: GUI 없이 자동 터널을 관리하고 설정 변경·포트 충돌·인증 실패를 처리합니다.
- `App`: Tk 메인 스레드에서 화면을 관리하고 큐로 백그라운드 이벤트를 받습니다.
- `TunnelService`: pywin32 서비스 수명주기를 `Runner`에 연결합니다.

## 연결 취소와 동시성

시작·중지·재연결 요청은 세대 번호를 바꿉니다. 연결 시도는 시작 당시 서버·암호·세대를 캡처합니다. 오래 걸린 연결이 끝났을 때 세대가 달라졌으면 소켓을 닫고 결과를 폐기합니다. 이전 인증 실패도 새 연결의 인증 실패로 처리하지 않습니다.

연결 상태 게시와 제어는 재진입 잠금으로 보호합니다. 이전 Transport의 keepalive 응답은 현재 연결의 생존 시간을 갱신하지 않습니다. 채널을 여는 동안 터널이 중지되면 뒤늦게 열린 채널과 클라이언트 소켓을 닫습니다.

## 설정과 보관

- 설정은 JSON, 망별 표시 스위치는 INI입니다. JSON의 터널 목록 전체를 검증한 뒤 표시 필터를 적용합니다.
- 사용자 범위 DPAPI와 PC 범위 DPAPI를 구분합니다. 새 제품이 기존 암호나 파일을 자동 탐색·복사하지 않습니다.
- 호스트 키는 사용자 SSH known_hosts와 프로그램 데이터 폴더 known_hosts를 사용합니다. 서비스는 모르는 키를 자동 승인하지 않습니다.
- 상태 파일은 서비스가 임시 파일을 쓰고 교체하여 GUI에 전달합니다.
- 소스와 EXE의 데이터 위치·서비스 이름·자동 실행 이름을 문서와 코드에서 일치시킵니다.
